# Lost Dream Messenger — Flutter-клиент

Кроссплатформенный клиент (Android, iOS, macOS, Windows, Linux, web) к Django-бэкенду
[`lost-dream-messenger`](../lost-dream-messenger): личные и групповые чаты, real-time через
WebSocket, presence, счётчики непрочитанного, JWT-авторизация.

До этого репозиторий был нативным Android-приложением на Kotlin/Compose. Оно удалено из рабочего
дерева, но лежит в git-истории (коммит `433543b`, каталог `app/`) и до сих пор полезнее текущей
Dart-версии в одном отношении: там контракт бэкенда выверен (порядок сообщений, `Origin` для WS,
личный канал уведомлений). При расхождениях смотреть туда.

> **Статус: сырой прототип.** REST-слой, модели и базовые экраны в целом рабочие, WebSocket-слой
> не поднимается, часть сценариев не доведена, тестов нет. Полный разбор — в [AGENTS.md](AGENTS.md):
> карта файлов, контракт бэкенда, 20+ известных дефектов с указанием строк.

## Запуск

1. Поднять бэкенд: `cd ../lost-dream-messenger && docker compose up` (Postgres, Redis, Daphne на `:8000`).
2. Проверить хост в `lib/config.dart` (`AppConfig.host`):

   | Цель | Хост |
   |------|------|
   | Эмулятор Android | `10.0.2.2:8000` (уже по умолчанию) |
   | Симулятор iOS / macOS | `127.0.0.1:8000` |
   | Реальное устройство | IP машины в локальной сети |

3. `flutter pub get && flutter run -d <device>`.

Хост зашит константой времени компиляции, поэтому смена окружения — это правка файла. Перевод на
`String.fromEnvironment` + `--dart-define=API_HOST=...` в списке TODO.

## Что работает

- вход и регистрация, хранение пары JWT, авто-refresh по 401 с одним повтором запроса;
- список чатов: превью последнего сообщения, время, бейдж непрочитанного (99+), pull-to-refresh;
- чат: история с дозагрузкой старых страниц, отправка через WS с фолбэком в REST, отметка
  прочтения при открытии, галочки ✓/✓✓;
- личный канал `ws/notifications/`: новое сообщение в другой чат, сброс бейджа, удаление и
  переименование чата, исключение из чата — без перезахода в список;
- создание личного чата (идемпотентно: существующий возвращается, а не дублируется) и группы
  с выбранными участниками;
- экран участников группы с ролью «админ»;
- профиль: чтение и `PATCH` своих полей, выход из аккаунта.

## Чего нет вовсе

- переименование группы и удаление чата из UI (методы в `ChatState` есть, не вызываются);
- добавление участника в группу (`Api.addMember` не используется);
- отображение presence: `onlineUsers` собирается из `initial_presence`/`user_status`, но не рисуется;
- `last_seen` в профиле и в списке чатов;
- пагинация списка чатов и учёт `next` в истории (видно только первые 50);
- оптимистичная отправка, очередь сообщений при обрыве связи, индикаторы «печатает»;
- push-уведомления, локализация (строки захардкожены по-русски), тёмная тема вручную (только seed Material 3);
- тесты: `test/widget_test.dart` — шаблонный счётчик, ссылается на несуществующий `MyApp`,
  поэтому `flutter analyze` и `flutter test` завершаются ошибкой.

## Платформы

Кроссплатформенность заявлена, но конфиги целей не доведены — release-сборки не выйдут в сеть:

- **Android**: в `android/app/src/main/AndroidManifest.xml` нет `INTERNET` (он только в debug/profile)
  и нет `usesCleartextTraffic` для HTTP;
- **macOS**: в `macos/Runner/DebugProfile.entitlements` и `Release.entitlements` нет
  `com.apple.security.network.client` — исходящие соединения блокирует песочница;
- **iOS**: в `Info.plist` нет `NSLocalNetworkUsageDescription` (нужно для обращения к IP в локальной
  сети на iOS 14+);
- **web**: не заработает без правок бэкенда — `CORS_ALLOWED_ORIGINS` разрешает только `:5173`,
  а `Origin` с порта Flutter-web не входит в `ALLOWED_HOSTS` (WS снова 403);
- **Linux/Windows**: ограничений нет, работают как есть.

Имя пакета в `pubspec.yaml` — всё ещё `lost_dream_messenger_android`.
